## 📖 Concept Explained Simply

DNS is a distributed hierarchical database. A client’s stub resolver normally asks a **recursive resolver** to find an answer. The recursive resolver follows referrals from root to top-level domain to authoritative servers, then caches the result.

| Record | Purpose |
| --- | --- |
| `A` | Name to IPv4 address |
| `AAAA` | Name to IPv6 address |
| `CNAME` | Alias to another name |
| `MX` | Mail destination |
| `NS` | Authoritative name server |
| `TXT` | Text-based policy or verification data |
| `PTR` | Address to name for reverse lookup |
| `SOA` | Zone authority and timing metadata |
| `SRV` | Service location |
| `CAA` | Certificate-authority permission |

TTL tells caches how long an answer may be reused. A low TTL can speed planned change propagation but increases query load; an expired TTL does not force every cache everywhere to update at the same instant.

`/etc/hosts` is a local static mapping checked according to the system’s name-service policy. `/etc/resolv.conf` traditionally identifies resolvers and search domains, but it may be generated by NetworkManager, systemd-resolved, containers, or orchestration software. Do not edit generated files blindly.

DNS usually uses UDP port `53`, but TCP is also required for cases such as larger responses, retries after truncation, and zone transfer.

## 🌍 Real Linux Example

A cloud application may resolve an internal database name differently inside a private network than on the public Internet. This **split DNS** is useful but makes the query source important during troubleshooting.

Kubernetes provides cluster DNS for Service discovery. A pod’s DNS failure can come from its resolver settings, cluster DNS, upstream DNS, policy, or the authoritative zone.

## 🛠️ Commands Introduced

### `dig` — Ask DNS Precisely

```bash
dig example.com A
dig example.com AAAA
dig @1.1.1.1 example.com A
dig +short example.com
dig +trace example.com
dig -x 192.0.2.20
```

The header shows status and flags. Question shows what was asked; Answer contains records and TTLs; Authority and Additional provide supporting delegation data. `+trace` follows delegation from the root and does not reproduce every normal recursive-resolver behaviour.

### `host` — Perform a Simple Lookup

```bash
host example.com
host 192.0.2.20
```

Useful for a quick forward or reverse answer, with less diagnostic detail than `dig`.

### `resolvectl` — Inspect systemd-resolved

```bash
resolvectl status
resolvectl query example.com
```

Shows per-link resolvers, search domains, routing domains, and query results where systemd-resolved is in use.

### `getent hosts` — Use the System Name-Service Path

```bash
getent hosts example.com
```

Unlike a direct DNS query, `getent` follows the host’s configured name-service order, which may include `/etc/hosts`, DNS, and other sources. This often resembles what applications see more closely.

## 💡 Caveman Tip

Compare three questions: what does DNS say, what does the operating system resolver return, and what did the application actually use?

## ⚠️ Common Mistakes

- Assuming every name-resolution failure is an authoritative DNS problem.
- Editing a generated `/etc/resolv.conf`.
- Forgetting cached answers and TTLs.
- Testing only `A` while the application prefers `AAAA`.
- Treating a successful direct `dig` query as proof every application resolves correctly.
